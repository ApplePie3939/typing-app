# フルスタ打 MVP 仕様書

Web ブラウザで遊ぶ、ITエンジニアのチャット返信を模したタイピングゲームの MVP 仕様です。  
技術選定・実装方式は本仕様の対象外です。

**正式名称（MVP）:** フルスタ打  
**UI 系統:** パターン C「スタートアップステッカー」（`mockups/pattern-c.html`）

---

## 1. プロダクト概要

相手から届いた社内チャットに対し、あらかじめ用意された返信文を**ローマ字入力**で打ち切り、「送信」するタイピングゲームです。

- 見た目は Slack 風のチャット画面
- 題材は、実際のエンジニア業務でありそうなコミュニケーション
- スコアの主軸は、寿司打における「給料」に相当する **ゲーム内年収**
- 世界観は「今どきの IT 企業 × トラブル多め × カタカナ語とボケが好きなフルスタック主人公」

プレイヤーは文章を自分で考えるのではなく、**提示された返信を正確かつ速く入力する**ことが目的です。

---

## 2. MVP の範囲

### 2.1 やること

| 領域 | 内容 |
| --- | --- |
| プレイ | 難易度選択 → 制限時間内に返信を打ち切る → 結果表示 |
| スコア | 1通送信ごとに年収を加算。結果画面で合計年収とサブ指標を表示 |
| 分析 | プレイごとにキー／指／2キー遷移のミス統計を保存し、専用画面で確認 |
| コンテンツ | 3難易度分のチャット題材（日本語表示・ローマ字入力） |
| UI | Slack 風チャット。白ベース＋ビビッドでポップ |

### 2.2 やらないこと（MVP 外）

- アカウント・ログイン・ランキング・シェア
- 自由作文、AI 生成によるその場の返信作成
- 音声、BGM 必須化、本格的なサウンドデザイン
- URL や長大なコードブロックなど、入力負荷が極端に高い題材
- 高度な分析（時系列グラフ、練習ドリル自動生成、キーボード可視化の精密ヒートマップなど）
- カスタムキーボード配列、かな入力、英語 UI
- マルチプレイ、チーム戦
- 設定の細分化（テーマ切替、キー配置エディタなど）

## 3. 世界観

### 3.1 舞台

- 今どきの IT 企業（スタートアップ〜成長期）
- 基本的にトラブルが多い
- 主人公は、フルスタックに Web アプリを開発する部署のメンバー

会社名（仮）: **株式会社カオスワークス**  
プロダクト名（社内）: **「シナジーボード」**（カタカナ社内用語が飛び交う架空プロダクト）

### 3.2 主人公

画面上の表示名は **あなた**（固定でよい）。性格はコンテンツ側で表現する。

- カタカナ語が大好き。使えば使うほどカッコいいと思っている
- 1つの返信につき、必ず1つは冗談・ボケを入れる

返信文はこの性格を必ず反映する。丁寧さや技術的な中身は難易度で変える。

### 3.3 よく出る相手・チャンネル

相手は固定の数名で十分。顔と役割がすぐ分かるようにする。

| 名前 | 役割 | 口調の目安 |
| --- | --- | --- |
| 佐藤 | PdM | 急ぎ・曖昧な依頼が多い |
| 田中 | シニアエンジニア | 冷静だが現場が荒れている |
| 鈴木 | カスタマーサポート | 顧客の怒りを優しく転送してくる |
| 山本 | デザイナー | 見た目とアクセシビリティの指摘 |
| 高橋 | CEO | 突然の方針変更 |

チャンネル例:

- `#web-fullstack`（メイン）
- `#incident-warroom`
- `#review-please`
- `#customer-voice`
- `#random`

## 4. ゲームの流れ

```
タイトル
  → 難易度選択
    → プレイ（チャット画面）
      → 結果（年収＋サブ指標）
        → もう一度 / タイトルへ / 分析を見る
タイトルから「分析」へ直接入れる
```

### 4.1 1プレイの構成

- **制限時間:** 60秒（全難易度共通）
- **開始:** 最初の相手メッセージが表示された状態。最初の有効な入力でタイマー開始
- **進行:** 返信を1通打ち切る（送信）たびに年収が加算され、次のメッセージが届く
- **終了:** 時間切れ。入力途中の通は不成立（その通の年収は 0）
- **メタファー:** 「今日のスプリント 1本」→ 終了は「退勤」

寿司打と同様、**件数固定ではなく、制限時間内に何通送れたか**が成績を分ける。

### 4.2 1通の入力ルール

1. 画面上に相手のメッセージ（日本語）と、打ち込む返信（日本語）を表示する
2. プレイヤーは返信をローマ字で入力する
3. 正しいキーのときだけ入力位置が進む
4. 間違ったキーはミスとしてカウントし、位置は進まない
5. 全文一致で自動送信。送信演出のあと次の通へ
6. バックスペースは「進んだ文字を戻す」用途では使わない（ミスしたら正しいキーを打ち直す方式）。誤って進まないため、戻る必要がない

ローマ字の揺れ（し = `si` / `shi` など）は、一般的な日本語タイピングゲームと同様に許容する。詳細な対応表は実装時の辞書に委ね、仕様としては「複数表記を受け入れる」とだけ定める。

## 5. 主要画面

### 5.1 タイトル

- ゲーム名、一言キャッチ
- スタート（難易度選択へ）
- 分析
- 遊び方（短く。初回だけモーダルでも可）

キャッチ案: 「社内チャットを打ち返せ。年収はタイピングで決まる。」

### 5.2 難易度選択

3枚のカード。世界観の肩書きを併記する。

選択後、カウントダウンなしでプレイ画面へ入ってよい（最初のキーで計測開始するため）。

### 5.3 プレイ（最重要）

Slack でやり取りしているように見せる。

必須要素:

- 左: ワークスペース／チャンネル一覧（装飾中心。MVP ではチャンネル切替プレイはしない）
- 中央: チャンネル名、メッセージ履歴、相手メッセージ、自分の返信プレビュー
- 下部: 入力欄。打ち込み対象の日本語と、入力済み／未入力の区別
- 上部または目立つ位置: **現在のゲーム内年収**、残り時間
- サブ: 現在の正確性、コンボ（連続正解キー数）は出してもよいが、主役は年収とチャット

プレイ中に出る自分の吹き出しは、入力の進行に合わせて文字が埋まっていく。送信完了後は通常の自分メッセージとして残る。

相手メッセージは「いま打つ通」を強調し、過去ログは薄く残す（画面が埋まって読みにくくならないこと）。

### 5.4 結果

退勤レポートのような見せ方。

必須:

- ゲーム内年収（メインスコア、最も大きく）
- 入力速度
- 正確性
- ミス数
- 最大連続入力数
- 送信できた通数（あると分かりやすいので MVP に含める）

操作:

- もう一度（同じ難易度）
- 難易度を変える
- 分析を見る
- タイトルへ

### 5.5 分析

累計（全プレイ合計）を基本とする。直近1プレイだけの切替があると望ましいが、MVP では累計のみでも可。

表示:

- 苦手キー: 入力回数、ミス回数、ミス率。上位を一覧
- 苦手な指: 物理キーと指の対応から集計した一覧
- 苦手な動き: 連続する2キー（バイグラム）のミス率上位

「まだデータが足りません」の空状態を用意する。

## 6. 難易度

| ID | 表示名 | 肩書き | 文章 | 記号・構造 | トーン |
| --- | --- | --- | --- | --- | --- |
| beginner | 初級 | 新米エンジニア | 短い。1〜2文 | 記号は少なめ。`#123` 程度は稀に可 | 丁寧で初々しい。カタカナは控えめ〜普通。ボケは弱い |
| intermediate | 中級 | 慣れてきたエンジニア | 少し長め。2〜4文 | `@メンション`、Issue/PR、軽い Markdown、英数字・記号 | 少し調子に乗っている |
| advanced | 上級 | つよつよエンジニア | 長め。複数行 | Markdown、引用、技術用語、英数字・記号を多め | 絶対的な自信。カタカナ密度が高い |

共通制約:

- どの難易度でも「1通にボケを1つ」
- URL、トークン、長いパス、コードのベタ貼りは出さない
- 個人情報・実在罵倒・差別表現は出さない
- 返信は声に出して読める日本語。ローマ字化したときに極端な長文にしない

分量の目安（日本語表示の文字数。空白・改行含む）:

- 初級: おおよそ 15〜40 字
- 中級: おおよそ 40〜80 字
- 上級: おおよそ 80〜140 字（改行 1〜3）

MVP の題材本数の目安:

- 各難易度 15 通以上（60秒で周回しうるため、重複してよい）
- 重複時は同じ通が連打されすぎないようシャッフル

## 7. スコア

### 7.1 メインスコア: ゲーム内年収

1通送り終えるたびに金額が加算される。プレイ終了時の合計がメインスコア。

単位は円。表示は `¥4,820,000` のように桁区切りする。  
「年収」はゲーム内の誇張スコアであり、実在の給与計算ではない。

### 7.2 1通の算出（ゲームデザイン）

実装式ではなく、バランスの意図を固定する。

```
獲得額 = 難易度の基準額 × 速度倍率 × 正確性倍率
```

端数は百円または千円単位に丸めてよい。

**基準額**

| 難易度 | 基準額 | 狙い |
| --- | --- | --- |
| 初級 | 120,000 | 短い通を多くさばく |
| 中級 | 220,000 | 1通の価値が上がる |
| 上級 | 350,000 | 通数は減るが単価は高い |

**速度倍率**

- その通のローマ字入力速度（1分あたりの正しい入力数）を、難易度ごとの目標速度と比較して 0.5〜2.0 に収める
- 速いほど高い。遅すぎても 0 にはしない（送り切れば最低でも半分）

目標速度の目安（ローマ字の正しいキー/分）:

- 初級 200 / 中級 280 / 上級 360

**正確性倍率**

- 正確性 = 正しいキー数 / （正しいキー数 + ミス数）その通分
- 100% で 1.0、ミスが増えると下がる。目安として 90% で約 0.8、50% で 0
- 正確性 50% 未満で送り切った場合は 0 円（稀）

**含めないもの**

- コンボによる加算（MVP では結果の「最大連続入力数」に出すだけ）
- 残り時間ボーナス
- 難易度間の隠し倍率

**1プレイの金額感（目安）**

うまくいったときの合計年収:

- 初級: 200万〜500万
- 中級: 400万〜900万
- 上級: 600万〜1,400万

初見でも 0 円に見えにくく、熟練すると桁が伸びて嬉しい範囲にする。

### 7.3 結果画面のサブ指標

| 指標 | 定義 |
| --- | --- |
| 入力速度 | プレイ全体の、1分あたり正しい入力数。画面上は「◯◯ キー/分」など分かりやすい単位 |
| 正確性 | 正しいキー / （正しいキー + ミス）の百分率。小数1桁 |
| ミス数 | 誤キーの総数 |
| 最大連続入力数 | ミスせずに連続して正解したキー数の最大 |

通数はメインスコアではないが、結果に表示する。

## 8. タイピング分析

### 8.1 記録するタイミング

各プレイ終了時に、そのプレイ分を累計データへ加算して保存する。  
ブラウザを閉じても残ることを想定する（実装手段は問わない）。

### 8.2 苦手キー

キー単位（物理キー、例: `A`, `;`, `-`）。

- 入力回数: そのキーを正解として要求された回数
- ミス回数: そのキーが次に要求されているときに別キーを押した回数
- ミス率: ミス回数 / 入力回数

一覧はミス率優先。入力回数が極端に少ないキーは「参考」扱い（例: 入力 20 回未満はランキングから除外、または注記）。

### 8.3 苦手な指

一般的な JIS キーボードのホームポジション対応で集計する。

- 左: 小指 / 薬指 / 中指 / 人差指
- 右: 人差指 / 中指 / 薬指 / 小指
- 親指（スペース）は独立して出してよい
- どれにも属さないキーは「その他」

指ごとの入力回数・ミス回数・ミス率を出す。

### 8.4 苦手な動き

連続する2キーの遷移（例: `R` → `E`、`Shift` を含む場合は「Shift付きのキー」として1イベントに正規化してよい）。

- 出現回数、ミス回数（2キー目でミス）、ミス率
- 上位のみ表示（例: 10件）
- 出現が少ない遷移は除外

シフト単体の押下を独立した「動き」として深掘りしない。

## 9. コンテンツ指針

### 9.1 題材の種類（必ず混ぜる）

- 確認・レビュー依頼
- バグ報告
- 進捗報告
- 質問
- 顧客への連絡（CS 経由を含む）
- @メンション
- 軽い Markdown（`**強調**`、`` `コード` ``、引用 `>`、箇条書き）
- Issue / PR 番号
- 英数字や記号を含む文

上級に偏らせず、中級から Markdown とメンションを出し始める。

### 9.2 入力負荷

避ける:

- `https://...` のフル URL
- 長いハッシュ、UUID、トークン
- ネストの深いコード
- 絵文字の連続入力を必須にする（表示用の絵文字は相手メッセージ側なら可）

使ってよい記号の例:

- `# @ * ` _ - , . ! ? : / （ ） 【 】`

スラッシュは短く（`LGTM` や `v1.2`、`#123` まで）。パスは `/api/users` 程度の短さに留める。

### 9.3 サンプル

**初級**

- 相手: `PR #123 のレビューお願いできますか？`
- 返信: `確認します。少々お待ちください。コーヒーはまだ飲めるので大丈夫です。`

- 相手: `本番のボタン、押しても反応ないです`
- 返信: `再現、いまから見ます。僕のボタン推し力不足ではないはず…！`

**中級**

- 相手: `@you 顧客からログインできないと連絡きてます。今日中に一次回答ほしいです`
- 返信: `` @suzuki 了解です。キャッシュ疑いで調査します。今日中に一次回答出します。僕のフルコミット、信じてください。 ``

**上級**

- 相手: `リリース後に 500 が出てます。影響範囲の共有お願いします`
- 返信:

```
> 500、確認しました
**仮説:** `/api/orders` のタイムアウトです。
暫定でリトライ入れて様子見します。
僕の勘はきょうもエグい精度です。
```

## 10. UI / UX 方針

採用系統は **C. スタートアップステッカー**。

- 大きな見出し、パステル＋原色、LGTM / hotfix 風のシール
- ホームはカードの弁当レイアウト
- プレイは Slack 風（サイドバー＋メッセージ＋下部入力）を崩さず、ヘッダーに残り時間と年収チップ
- 結果は「退勤シール」、分析はウィークポイントのダッシュボード

系統が変わっても守る点:

- Slack 風の骨格（サイドバー、チャンネル、メッセージ列、下部入力欄）
- 白をベースにする
- ビビッドなアクセントを複数使う（単色のコーポレートにしない）
- 年収はプレイ中から常に見える
- 打ち込み対象と、今どの文字かがはっきり分かる
- ミスした瞬間は入力欄で分かる（色や短い反応）。減点演出で画面全体を赤く埋めない
- 送信成功時は金額が加算されるのが分かる
- スマホ最適化は MVP 対象外。デスクトップ想定（キーボード前提）
- 文字サイズはタイピングゲームとして余裕を持つ。装飾のために本文を小さくしない

## 12. 受け入れの目安（MVP 完成の定義）

1. 3難易度で 60秒プレイが最後までできる
2. 返信の表示が日本語、入力がローマ字で成立する
3. 送信のたびに年収が増え、結果画面で合計とサブ4指標が出る
4. 複数プレイ後、分析画面でキー／指／2キー遷移が見られる
5. 題材が仕様のジャンルと世界観を満たし、URL 級の高負荷題材がない
6. 画面が Slack 風で、白ベースかつカラフルである
